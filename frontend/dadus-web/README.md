# DADUS AI web

An Angular text-chat client for the local DADUS AI development skeleton. The API and database setup are documented in the repository's root README.

## Run

Use Node.js 24.15 or newer in the Node 24 release line and npm 11 or newer.

```bash
npm ci
npm start
```

The development server binds to `127.0.0.1:4200`. Its `/api` proxy targets the API on `127.0.0.1:5088`; start the backend and database first. API requests use relative same-origin paths. No provider keys belong in Angular configuration or browser storage.

```bash
npm run build -- --configuration production
CI=true NG_BUILD_MAX_WORKERS=2 npm test -- --watch=false
```

Production build files are in `dist/dadus-web/browser`. Deployment, public authentication and hosting are separate work.

## Behavior

- Text messages, conversation selection, new chats and paginated history.
- Marathi/Hindi/English input, a visible loading state, and draft preservation when a message fails.
- Server replies and errors rendered as escaped plain text, preserving line breaks.
- Visible demo-mode labels whenever the API uses sample replies. These replies are not generated by an AI model.
- A random anonymous browser-session identifier in `localStorage` scopes development history. This is not account authentication; losing browser storage loses access through this client to that session's history.
- Mobile navigation and keyboard support: Enter sends, Shift+Enter adds a line. IME composition is not submitted prematurely.

## Agents and tools

The role picker loads the .NET agent catalog: Companion for everyday conversation, Planner for practical next steps, and Coding helper for explaining or reviewing code. A role change applies to the next message in the current conversation; it does not relabel earlier messages or reset shared history.

The agents have read-only calculation and current-time tools. In demo mode, try `/calculate (12+3)*2` or `/time Asia/Kolkata`; these tools run even though the surrounding reply is a labeled sample. Live OpenAI agents can request those tools through the server when provider access is configured. The coding role does not execute code.

The latest-response panel identifies the responding role and displays tool summaries as escaped plain text. These run details are not stored in chat history, so they disappear when switching or reloading conversations. If the catalog cannot be loaded, the client leaves Companion available and shows a retry option.

Microphone access, wake-word detection, real-time voice, mobile shells and personal memory are not implemented in this milestone.
